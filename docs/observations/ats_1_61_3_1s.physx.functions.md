# ATS 1.61.3.1s — known PxScene method function addresses

Reference catalog used by `walkercore::PhysXAdapter::ResolveKnownMethods`
to map vtable entries to method names. Image base = `0x140000000` (PE
load address). VA = image base + RVA.

| Method | VA | RVA | Slot | Source |
| --- | --- | --- | --- | --- |
| `PxScene::release`     | `0x141AE07B6` | `0x1AE07B6` | TBD | LEA -> "PxScene::release(): Scene is still being simulated" |
| `PxScene::addActor`    | `0x141AE0B62` | `0x1AE0162` | TBD | LEA -> "PxScene::addActor() not allowed" |
| `PxScene::simulate`    | `0x141AE4D80` | `0x1AE4380` | TBD | LEA -> "PxScene::simulate() ..." |
| `PxScene::shiftOrigin` | `0x141AE6C28` | `0x1AE6228` | TBD | LEA -> "PxScene::shiftOrigin() not allowed" |

The "Slot" column is populated by `ResolveKnownMethods` at runtime —
when a vtable candidate's pointer at `vtable_base + N*8` equals one of
the VAs, N is the slot for that method.

## Provenance

Each row has a documented LEA-ref matching chain in
`rea/scripts/physx-vta-scan/README.md` § Hallazgos confirmados. The
catalog was produced by:

1. Reading the open-source PhysX 3.4 PxScene.h header to enumerate
   virtual methods.
2. Locating each method's LEA instruction in `.text` by following the
   references to the matching `PxScene::<method>` assertion string
   stored in `.rdata`.
3. Recording `image_base + RVA` as the method's absolute VA.

## What it unlocks

- **In-process slot resolution**: when the DLL is loaded by ATS,
  `PhysXAdapter` can scan `.rdata`, find a candidate vtable, and
  resolve `release` / `addActor` / `simulate` / `shiftOrigin` slots
  without needing a live PxScene instance or full Ghidra analysis.
- **Cross-validation against TMRealWalk**: TMRealWalk uses the same
  string-based detection. If our ResolveKnownMethods finds >=2
  matches and the slot offsets fall in the published PhysX 3.4 SDK
  order, we have identified the vtable with very high confidence.

## Updating for a new ATS build

When a future ATS patch changes any of these methods:

1. Re-run `python scripts/physx-vta-scan/find_string_refs.py "<path>\amtrucks.exe"`
2. Update the VA in `src/provider/PhysXAdapter.cpp` (the
   `kPhysXKnownMethods` array).
3. Add a VersionEntry row for the new build SHA in
   `src/domain/VersionTable.cpp` carrying the new VA list.

If the SDK devirtualises one of the methods entirely, replace its
catalog row with an empty name (or drop it). The matcher is
defensive — missing catalog rows are simply not matched.
